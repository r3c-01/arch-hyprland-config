# Isolated Quickshell smoke-test checklist

Status: **not executed during repository preparation**. Record actual results and versions rather than treating this checklist as test evidence.

- [ ] **Use an isolated desktop.** Prefer a disposable VM with a snapshot, its own Hyprland session, D-Bus, audio services and test data. A separate account/session is useful but shares system-wide services; changing HOME alone does not isolate anything beyond selected file paths. Do not use production dotfiles, credentials or host state.
- [ ] **Stage only public source.** Verify the archive checksum and its manifest, extract into the disposable environment and install its configuration/helper files following README.md. Supply a non-sensitive wallpaper and new empty task/activity state. Record Hyprland, Qt, Quickshell and distribution versions. Do not import `work/excluded/` or unrelated configuration.
- [ ] **Launch in foreground.** In separate terminals in that disposable session, run `qs -p "$HOME/.config/quickshell-caffeine"`, `qs -p "$HOME/.config/quickshell-activity"`, `qs -p "$HOME/.config/quickshell"`, then `qs -p "$HOME/.config/quickshell-control"`. Keep terminal diagnostics. Avoid running another notification daemon concurrently. Confirm no missing modules, component-load errors or binding loops.
- [ ] **Check rendering and IPC.** Verify the bar/dock on available outputs, workspace updates, icon visibility, clock/calendar position, Escape/close behavior, media/tray popups and control-center opening from the bar. With Cava installed and test audio playing, verify the spectrum and its toggle; absence of audio should not prevent other components loading.
- [ ] **Check isolated local state and reversible controls.** Add, edit and complete a disposable task; confirm calendar synchronization and persistence after restarting the control center. Verify activity totals advance for a test app and pause during idle. Test caffeine on/off, checking it returns off. Inspect metrics/process rows first; test audio/device/radio changes only in the disposable environment, restoring their initial state.
- [ ] **Separate network and high-impact tests.** Initially leave probes off and avoid socket diagnostics if no DNS traffic is wanted: socket inspection may perform reverse lookups. Enable explicit DNS/trace/public-IP checks only with intended test-network access. Do not click reboot, shutdown, suspend or terminate arbitrary processes. Test lock/unlock only with a known disposable account password and VM-console recovery. Test process SIGTERM only on a disposable process created for that purpose. Test Game Mode/recording separately after configuring the required replay service; verify restoration and recorder identity rather than assuming the offline tests prove live safety.
- [ ] **Stop and inspect.** Close each test instance through its own foreground terminal; avoid broad kill commands. Confirm its Cava/Python workers exit and idle inhibition is released. Note every failure, warning and skipped dependency. Preserve logs locally and redact usernames, paths, app names, task text and network addresses before sharing. Discard or revert the disposable environment when finished.

A successful smoke test covers only the recorded environment and actions. Multi-monitor hardware, GPU drivers, authentication, permissions, recovery after crashes and clean-machine setup require their own evidence.
